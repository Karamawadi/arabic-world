# عالم العرب — Arabic World

لعبة Sandbox ثلاثية الأبعاد بهوية عربية وإماراتية تعمل في المتصفح: بناء وتكسير مكعبات، استكشاف، بقاء، ولعب جماعي حقيقي بكود العالم.

## التشغيل

```bash
npm install
npm run build
npm start
```

أو بنقرة واحدة: `start.bat` على Windows، و`start.command` على Mac، و`start.sh` على Linux (يثبّت ويبني عند أول مرة ثم يفتح المتصفح).

- واجهة اللاعبين: `http://localhost:8080/play`
- لوحة الإدارة: `http://localhost:8080/admin`
- يتطلب Node.js 22.5 أو أحدث (يستخدم `node:sqlite` المدمجة).

عند أول تشغيل يُنشأ حساب المدير `admin` بكلمة مرور عشوائية تُحفظ في `data/admin-credentials.txt`.
لتحديدها مسبقاً: `ADMIN_USERNAME=... ADMIN_PASSWORD=... npm start`.

متغيرات البيئة: `PORT` (افتراضي 8080)، `DATA_DIR` (افتراضي `./data` — قاعدة البيانات والأصوات المرفوعة).

### النشر على نطاق عام

```bash
docker build -t arabic-world .
docker run -d -p 8080:8080 -v aw-data:/data -e ADMIN_PASSWORD=change-me arabic-world
```

ضع الخدمة خلف وكيل عكسي يوفّر HTTPS ويدعم WebSocket (المسار `/ws`). خادم واحد يكفي؛ حالة الغرف في ذاكرة العملية، لذا التوسع الأفقي يحتاج توجيه كل عالم إلى عملية واحدة.

## المعمارية

| المجلد | المحتوى |
|---|---|
| `shared/` | مولّد العالم الحتمي (ضجيج، تضاريس، كهوف، أشجار، منشآت) + تعريف موارد الإدارة. يعمل في الخادم والمتصفح معاً. |
| `server/` | Express API، خادم WebSocket للغرف، قاعدة SQLite، المصادقة والصلاحيات. |
| `src/engine/` | المحرك (Three.js): القطع والشبكات، الفيزياء، السماء والطقس، الشخصيات، الصوت، الشبكة. |
| `src/play/` | واجهة اللاعبين (React). |
| `src/admin/` | لوحة الإدارة (React) — حزمة مستقلة. |

**الخادم هو المرجع**: يولّد التضاريس بنفس مولّد العميل، فيتحقق من كل تعديل (الصلاحية، المسافة، حدود العالم، المعدّل، وتطابق الحالة السابقة لمنع التعارض)، ويحسب الإحصائيات والإنجازات والمهام بنفسه. العميل لا يستطيع منح نفسه إنجازاً.

**التخزين**: يُحفظ الفرق فقط (المكعبات المعدّلة لكل قطعة) في `world_chunks`، مع حفظ تلقائي دوري ونسخ احتياطية يومية ويدوية.

## نظام غرف اللعب والجلسات

- عدد محدود من الغرف المتزامنة (افتراضياً 10)، لكل غرفة سعة (5 لاعبين) ومدة جلسة (60 دقيقة). كلها تُعدَّل من لوحة الإدارة ← إعدادات اللعبة.
- المؤقت يبدأ عند دخول أول لاعب ويحسبه الخادم؛ تنبيهات قبل 10 و5 ودقيقة.
- لا يُطرد أحد لقلة النشاط. مقعد المنقطع يُحفظ دقيقتين، والغرفة الفارغة تُحرَّر بعد 3 دقائق.
- عند امتلاء الغرف يدخل اللاعب طابوراً بالدور مع الوقت المتوقع، ويدخل تلقائياً عند توفر غرفة.
- عند انتهاء الجلسة: يُحفظ العالم، تُحذف الدردشة ومواقع اللاعبين، وتعود الغرفة متاحة. العوالم المعلَّمة «جلسة مؤقتة» يُمسح بناؤها أيضاً.
- سجل الجلسات في جدول `room_sessions`. لتعطيل النظام كلياً: `room_system_enabled = false`.

## ملاحظة حول Supabase

المواصفات اقترحت Supabase. هذه النسخة تستخدم خادماً مستقلاً مع SQLite لأن اللعب الجماعي يحتاج خادماً مرجعياً على أي حال، ولعدم توفر مشروع Supabase أثناء البناء. ما يقابل Row Level Security مطبّق في طبقة الـ API (كل استعلام مقيّد بمالك السجل أو بصلاحية إدارية). الجداول مطابقة للقائمة المطلوبة، والانتقال إلى Postgres/Supabase يتطلب استبدال `server/db.ts` وطبقة المصادقة.

## حدود معروفة

- الحيوانات ومخلوقات الليل تُحاكى محلياً لدى كل لاعب ولا تُزامَن بين اللاعبين.
- الماء ثابت (لا يتدفق عند الحفر بجانبه).
- الحقيبة يديرها العميل وتُحفظ في الخادم (الإنجازات لا تعتمد عليها).
- عند دخول العالم تُرسل كل التعديلات دفعة واحدة؛ مناسب للعوالم المحدودة الحجم، وللعوالم الضخمة جداً يُفضّل لاحقاً الإرسال حسب القطعة.
- العرض عبر WebGL (Three.js). لا يوجد مسار WebGPU.
- لا توجد قائمة أصدقاء؛ الدعوة تتم بالكود أو برابط المشاركة.
